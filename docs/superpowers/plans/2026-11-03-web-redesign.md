## Decisions (from brainstorming, 2026-11-03)

| Question | Decision |
|---|---|
| Audience | Presentation / showcase first |
| Structure | **Two pages**: an intro page (`/`) that explains the project, then the workstation (`/app.html`) where photos are uploaded and reconstructed |
| Intro hero | H1: full-screen featured reconstruction (templeRing cloud + its ring of 47 recovered cameras; *now the full Temple, 312 photos, in a ring of 36 of its cameras*), survey details (fiducial crosses, monospace data strip), then the five-frame "how it works" strip |
| Workstation | The mock-up's layout: viewer centre with tabs, pipeline + summary right, run panel left, ground truth + console bottom. Running and results are one screen |
| Colour | Palette 1, graphite + survey teal: one accent, used for cameras, the primary action and active states. Final check with `impeccable` (colour) |
| Showcase data | Committed under `src/web/static/showcase/`, generated by a script from a real run, so the intro works on a fresh clone and offline (except fonts / three.js from CDN) |
| Left out | Projects, user/settings icons, system meters, coverage/overlap metrics: nothing in the app backs them |
| Build | No build step, no new runtime dependency: FastAPI + static HTML/JS, three.js from the CDN as before |

## Phases

Every backend task is test-first (`tdd` skill): failing test, implement, task tests, then
`pytest -q`. Frontend tasks are checked in Chrome (desktop 1440 px and phone 390 px,
console free of errors) since the repo has no JS test runner. After every two phases a
checkpoint (saved rule): `/code-review`, `systematic-debugging` for anything failing,
`tdd` for missing tests, `simplify`, then fix.

### Phase 1 — Backend data the new pages need (TDD)

1. **Per-stage numbers in `report.json`** (`src/web/report.py`): a `stages` object —
   features (median and total per image, cached), matches (pairs, putative matches,
   cached), verification (verified pairs, inliers, inlier ratio), initial pair (names),
   reconstruction (registered cameras, landmarks), filter (kept / total). Built from the
   in-memory `PipelineResult`, null for stages that did not run.
2. **Run thumbnails**: the job writes up to 12 small JPEG thumbnails (`thumbnails/`,
   longest side 240 px) into the run folder before the uploads are deleted, so previous
   runs can show their photos. Listed by `GET /api/jobs/{id}/files` like any output.
3. **Two pages served**: `/` the intro, `/app.html` the workstation; existing `#job=` links
   move to `/app.html#job=`. Cache-Control on every page and script (existing test
   extended).

### Phase 2 — Shared design system and viewer

4. **`tokens.css`**: colours (palette 1, dark; the intro and workstation are dark-only
   like the viewer), type scale (Archivo display, Atkinson Hyperlegible Next body,
   JetBrains Mono data; *changed later to Fraunces, IBM Plex Sans and IBM Plex Mono*), spacing, radii, focus ring, reduced-motion rule. `app.css` and
   `intro.css` build on it.
5. **`viewer.js` upgrades** (ported from the prototype): round points, glowing camera
   markers, frustums sized to the camera ring, perspective/orthographic, layers (cloud,
   cameras, capture path, grid), auto-orbit (off under reduced motion), orbit/pan tools,
   camera picking for a hover/click label, `reveal(share, cameras)` for the replay,
   transparent background over a radial glow.

## Exit criteria

- The intro explains process, architecture and results from committed real data, and
  works on a fresh clone.
- The workstation does everything the current page does, plus the live pipeline column,
  tabs, viewer upgrades and replay.
- `pytest -q` green; no console errors; both pages usable at 390 px; every audit finding
  fixed or explicitly declined in this file.

## Findings kept or declined (with reasons)

Design inspector (`design-taste-frontend`, `inspect.mjs`) and detector (`impeccable`):

- **Three typefaces, monospace for numbers, hairline rules, fiducial crosses (drawn with
  CSS gradients), the faint glow behind the object:** kept. They are the brand committed
  in PRODUCT.md (survey-instrument language); `impeccable`: the brief wins over a
  saturated-pattern warning.
- **"Off-centre" 56 px / 72 px margins at 1440 px:** the extra 16 px on the right is the
  scrollbar; the content margins are equal.
- **No video:** none would be honest; the hero's live, orbiting 3-D view is the moving
  picture.
- **Ragged rows and "mixed-font headline" on the workstation:** a three-column work
  surface whose columns end at different heights by nature; the mixed-font items could
  not be located from the report and nothing on screen mixes faces within a heading.
- **`impeccable` detector, empty `<img>` in the lightbox:** filled when a figure opens.
- **Stock photographs (picsum) offered by the direction sheet:** not used; every picture
  is the project's own (photos, frames, live view).

Web Interface Guidelines audit, declined:

- **Vendor three.js instead of the CDN:** the original Phase 12 decision (no build step,
  CDN with a pinned version) stands; the page says it needs the network for three.js and
  the fonts.
- **`Intl.DateTimeFormat` for clocks and dates, units after U+00A0, the selected tab in
  the URL, opening a run on Enter instead of on `change` of the select:** polish without a
  real user problem in a local, single-user tool; left as they are.
- **Section links in the intro's nav below 1000 px:** the page is short and linear; the
  call to action stays.
